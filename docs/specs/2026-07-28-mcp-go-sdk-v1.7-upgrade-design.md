# MCP Go SDK v1.7 Upgrade Design

## Goal

Upgrade Rocketclaw's external MCP HTTP server from `github.com/modelcontextprotocol/go-sdk` v1.6.1 to v1.7.0 and serve protocol version `2026-07-28` without changing the public `session_prompt` behavior.

## Scope

The change covers the shared module dependency and vendored dependency tree plus `internal/rocketclaw/externalmcp`, which is the MCP server launched by `cmd/rocketclaw`.

The following behavior remains unchanged:

- the `/mcp` endpoint;
- Basic Authentication on every HTTP request;
- the `session_prompt` tool name, input and output schemas, content, and structured result;
- application-level conversation continuity through `external_conversation_id`;
- support for legacy MCP clients through SDK protocol negotiation.

## Transport Design

Construct the streamable HTTP handler with explicit `mcp.StreamableHTTPOptions` containing:

- `Stateless: true`, enabling protocol version `2026-07-28` and removing transport session IDs;
- `PropagateRequestCancellation: true`, cancelling a blocking tool handler when the HTTP request is aborted because its result can no longer be delivered.

Stateless MCP transport matches Rocketclaw's existing model. Conversation state is selected explicitly by each `session_prompt` request's `external_conversation_id`; the server does not use server-initiated calls, subscriptions, roots, sampling, logging, standalone SSE, or stream resumability. No Rocketclaw configuration flag or compatibility mode is needed.

The same `mcp.Server` may continue to be returned for every request. The SDK creates an ephemeral MCP session for each stateless request while the server's registered tool remains immutable.

## Dependency Update

Update the root module from SDK v1.6.1 to v1.7.0, tidy module metadata, and regenerate `vendor`. Review all resulting direct and indirect dependency changes rather than manually editing generated dependency files.

Do not set any `MCPGODEBUG` compatibility flags. The new default error wrapping, HTTP error decoding, request-body limit, tool schema validation, and annotation serialization are intentional SDK v1.7 behavior.

## Tests

Add one focused integration test in `internal/rocketclaw/externalmcp/server_test.go` that connects with the v1.7 client and verifies:

- the negotiated protocol version is exactly `2026-07-28`;
- the `session_prompt` tool remains discoverable and callable;
- requests and responses do not use `Mcp-Session-Id`;
- closing a stateless client session does not require transport-session deletion.

Retain the existing tests as the behavioral regression suite for schema generation, tool results, attachments, Basic Authentication, and application conversation continuity. Do not add tests for SDK features Rocketclaw does not use.

Where practical, capture HTTP headers with the existing custom round tripper rather than adding another server or transport abstraction. Keep any test-only change local to `server_test.go`.

## Verification

Run the focused external MCP package tests first, then the repository-required checks:

```sh
gofmt -w internal/rocketclaw/externalmcp/server.go internal/rocketclaw/externalmcp/server_test.go
go test ./internal/rocketclaw/externalmcp -count=1
go test ./...
make lint
make test
```

Inspect the final change with `jj diff --git`, including module and vendor changes. Confirm the Rocketclaw source CLOC and coverage budgets remain satisfied through `make test`.

## Documentation Impact

The README describes application-level external MCP behavior rather than wire-protocol or SDK versions. Because the endpoint, authentication, tool contract, and conversation semantics do not change, no README update is needed.
