This records evidence for [Fast conversation sidebar](../plans/2026-09-09-fast-conversation-sidebar.md). It is not rollout approval. Independent follow-up confirmed all review fixes; remote measurements below cover an earlier candidate.

## Migration-only rehearsals

Fresh copies were restored sequentially into isolated PostgreSQL 18 containers with named volumes. The probe only opened and closed the real store. No application, backfill, connector, model, scheduler, or delivery workload ran on customer copies.

| Source | Migration count | Preserved rows | Existing tables | Migration time |
| --- | --- | ---: | ---: | ---: |
| Gene | 5 → 10 | 376 | 10 | 0.803 s |
| Wallace | 5 → 10 | 39,508 | 11 | 0.064 s |
| Local | 8 → 10 | 7,226 | 11 | 0.066 s |

Order-independent fingerprints of existing-column row values, column metadata/defaults, and original ledger dates were preserved. A second startup left each ledger unchanged. Dumps were streamed rather than saved. Exact rehearsal containers and named volumes were removed; later successful Docker listings independently confirmed absence. These results establish migration preservation, not customer-data application performance.

## Synthetic runtime measurements

Measured against canonical revision `a044a1a6`, before the later stored-title and completeness simplifications. Results are descriptive, not timing gates.

| Recorded conversations | Initial histories | Preview bytes | Authenticated RPC ready | Zero missing summaries observed | First HTTP row, median | Full HTTP stream, median |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 446 | 446 | 17,800,000 | 152.9 ms | 1.568 s | 8.36 ms | 60.52 ms |
| 7,361 | 17,582 | 17,664,000 | 2.075 s | 165.351 s | 12.04 ms | 126.27 ms |

The larger fixture includes unrecorded orphan histories. Both fixtures use deterministic, highly compressible text and tied microsecond timestamps; they do not approximate real-customer replay sizes or content distributions. Preview bytes are decoded UTF-8 bytes, not wire bytes.

Startup timing begins after compilation, initial migration and fixture creation. It includes actual `backend.Run` startup and ends at a successful authenticated identity RPC. Backfill completion is observed through SQL, with polling delay included. At RPC readiness, 445 and 17,582 summaries respectively remained missing.

During backfill, 58 and 6,876 writes succeeded, alongside 10 and 805 HTTP list enumerations. Write p95 latency was 21.02 ms and 13.98 ms. Writes targeted separate synthetic history-only conversations: this tests shared runtime/database contention, not forced same-row contention or model throughput.

HTTP medians use three post-backfill runs through the real Go RPC and tRPC handler. Every full result was checked for IDs, full previews, agents and microsecond timestamps. Full transfer ends only after successful stream exhaustion. The default 4 MiB gRPC receive limit remained enabled. The probe used loopback TCP for gRPC because its scratch path exceeded macOS Unix-socket limits; production socket behavior has separate integration tests.

These are JavaScript iterator-delivery timings, excluding browser paint and remote navigation. They do not establish the directional 100 ms saved-display or 300 ms fresh-screen targets.

## Reconciliation benchmark

The isolated reconciliation change `c7cde71f`, incorporated into `87e4e8ed`, was measured against `f3901660` with fixed synthetic rows, one envelope per row and a prepopulated baseline. Fixture construction is excluded; timing includes iterator consumption, accumulation, list merging and a trivial publication callback. One warmup was excluded and five runs supplied each median.

| Runtime | Rows | Baseline median | Coalesced median | Publications before → after |
| --- | ---: | ---: | ---: | ---: |
| Bun | 446 | 4.307 ms | 0.120 ms | 447 → 2 |
| Bun | 7,361 | 899.111 ms | 0.970 ms | 7,362 → 2 |
| Chrome | 446 | 3.000 ms | 0.100 ms | 447 → 2 |
| Chrome | 7,361 | 666.500 ms | 1.300 ms | 7,362 → 2 |

The first useful row publishes immediately; later display work coalesces over 16 ms without delaying transport consumption. Exhaustion and ordinary stream failure flush pending accepted rows; abort and identity mismatch suppress publication. Full-list work remains per publication: slow arrivals separated by timer windows can still rebuild each time. These are burst improvements, not a universal linear-time bound.

Helper timings exclude network, React, search, storage and paint. A separate local actual-App probe observed storage-to-first-DOM gaps of 12.2–13.6 ms on three saved reloads, using a constant-work observer. This is neither a before/after comparison with the remote fixture nor an explanation of its approximately one-second delay. The remote reconciliation-candidate results above retain that delay.

## Review dispositions

Eleven native reviewers inspected revision `b2f8b063` against base `282a60e7`. A separate validator checked the deduplicated findings. These four corrections are implemented with combined browser coverage:

1. Clear prior saved rows promptly when session enumeration detects an owner mismatch or authentication failure, even if identity revalidation is still pending.
2. Keep conversation-local busy state and late prompt callbacks isolated when navigating between sessions.
3. Prevent an old enumeration in another tab from restoring previews after successful history deletion in the shared browser store.
4. Avoid copying and reconciling the entire accumulated list for every single-row stream envelope.

The fifth finding, sync summary-write rollback coverage, is resolved: a real database constraint rejects the write with a live context. The test verifies unchanged history, summary and schedules, no premature delivery or queued-work release, and correct producer-before-human delivery after retry. Migration tests also now cancel a startup proven to be waiting for the advisory lock, then verify successful completion by the other startup and absence of remaining locks. Both focused tests passed under the race detector; repository Go tests, lint and `make test` passed after these additions.

The validator rejected an arbitrary test-file size limit and a proposed Slack request timeout: neither follows from the applicable project contract. Existing lifecycle cancellation remains required.

Independent follow-up on `87e4e8ed` confirmed the coalescing, cross-tab deletion and sync rollback fixes. It requested two further corrections: same-owner identity reconfirmation must resume enumeration even when React batches away the intermediate pending state, and a delayed session-creation result must not adopt or navigate a newer draft. Both were reproduced in Chromium and fixed in `07a6f250`. A second independent inspection confirmed both repairs with no concrete residual finding. The browser cases cover immediate identity fetch/JSON completion and a held creation response across session/home navigation, including unchanged destination draft and URL and exactly one original prompt submission.

The remote receipt and exact cleanup evidence have been inspected and incorporated above. The evidence map covers the implementation requirements with the stated revision and measurement boundaries. Slack installation scopes/subscriptions and current production health have not been certified; customer-copy application criteria were superseded by migration-only authorization. No merge or coordinated deployment has been performed.
